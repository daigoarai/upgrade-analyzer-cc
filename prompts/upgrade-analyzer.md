# Upgrade Analyzer - Codex CLI版

このプロジェクトは、ソフトウェアのバージョンアップ影響分析を自動化するツールです。

## カスタムコマンド

### /prompts:upgrade-analyzer

**説明**: ソフトウェア製品のバージョンアップ影響分析レポートを生成します。

**構文**:
```
/prompts:upgrade-analyzer <製品名> <バージョンFrom> <バージョンTo> [プロジェクト情報]
```

**引数**:
- `<製品名>`: アップグレード対象の製品名（必須）
- `<バージョンFrom>`: 現在のバージョン（必須）
- `<バージョンTo>`: アップグレード先のバージョン（必須）
- `[プロジェクト情報]`: プロジェクトの文脈・背景・目的・特性（オプション）

**例**:
```
# 基本的な使用方法
/prompts:upgrade-analyzer Next.js 15.4 15.5.3

# プロジェクト情報を含めた使用方法
/prompts:upgrade-analyzer Next.js 15.4 15.5.3 "Eコマースサイト、月間100万PV、決済機能とカート機能が重要、SEOとパフォーマンスが最優先"

/prompts:upgrade-analyzer React 18.2.0 18.3.1 "社内の勤怠管理システム、認証とアクセス制御が重要、ダウンタイム許容度低"

/prompts:upgrade-analyzer PostgreSQL 14.1 15.0 "金融系SaaSのデータベース、トランザクション整合性とセキュリティが最重要、24時間365日稼働"

/prompts:upgrade-analyzer TypeScript 5.0 5.3 "大規模なモノリポ構成、マイクロサービス30個以上、型安全性とビルド速度が重要"
```

**動作**:
このコマンドを実行すると、以下のプロンプトが自動的に実行され、**レポートが自動的に`reports/`フォルダに保存されます**：

**⚠️ 重要**: レポート生成後、**必ず以下の手順でファイルを自動保存してください**：
1. 生成されたレポートを`reports/{製品名}_{バージョンFrom}_to_{バージョンTo}_{YYYYMMDD}_{HHMMSS}.md`として**自動的に新しいファイルで保存**
2. **重要**: 既存ファイルは上書きせず、実行のたびに新しいファイルを生成
3. **必須**: ファイル保存を完了し、ファイルパスを報告
4. **確認**: 保存完了を確認し、レポートの品質チェックを実施

## 調査対象

上記の製品について、バージョンFrom から バージョンTo へのバージョンアップを予定しています。

**⚠️ 必須調査手順**:
1. **リリース状況の検証**: 指定されたバージョンが実際にリリースされているか確認
2. **中間バージョンの特定**: FromとToの間にある全バージョンを特定
3. **段階的差分分析**: 各バージョン間の変更点を個別に調査
4. **累積影響の評価**: 全変更点を統合して総合的な影響を分析

差分を明確にして、テストする観点を整理して下さい。

**⚠️ 重要**: プロジェクトコンテキストが指定されている場合は、そのプロジェクトの特性・目的・重要な機能を考慮して、以下の項目を調整してください：

1. **重要度の判定**: プロジェクトにとって影響が大きい変更を高優先度に
2. **テスト観点**: プロジェクトの重要機能に関連するテストを重点的に
3. **リスクアセスメント**: プロジェクト固有のリスクを追加
4. **成功基準**: プロジェクトのKPIに合わせた指標を設定

## 調査項目

以下の観点で網羅的に調査してください：

### 1. メタ情報
- **調査日**: 現在の日付を動的に取得（YYYY-MM-DD形式）
- **リリース状況確認**: 指定バージョンのリリース状況（リリース済み/未リリース/最新バージョン）
- **中間バージョン一覧**: FromとToの間にある全バージョンのリスト
- **セマンティックバージョン分類**: MAJOR/MINOR/PATCHの判定
- **重要度**: 高/中/低（プロジェクトコンテキストを考慮）
  - **プロジェクトコンテキストが指定されている場合**: プロジェクトの特性を考慮した重要度を記載
  - 例: "一般的には中程度だが、Eコマースサイトの決済機能に影響するため🔴高"
- **プロジェクト固有の考慮事項**（プロジェクトコンテキストが指定されている場合）

### 2. 差分サマリ
- **バージョン範囲**: From → To の全バージョン
- **総変更数**: 全バージョンでの累積変更数
- **Breaking Changes数**: 互換性破壊の変更数
- **セキュリティ修正数**: CVE修正の数
- **新機能数**: 追加された機能の数
- **バグ修正数**: 修正されたバグの数
- **プロジェクトへの影響度**: プロジェクトコンテキストを考慮した総合的な影響評価

### 3. バージョン別変更ログ（全件）
- From、全中間バージョン、To を含む**すべてのバージョン**を古い順に並べ、それぞれ `#### {バージョン番号}（リリース日: YYYY-MM-DD）` の小見出しを用意
- 各バージョン小見出しでは、そのバージョンの**全変更項目**（Breaking / Feature / Security / Bugfix / Deprecation など）を漏れなく列挙し、省略しない  
  - 各行に変更種別（絵文字やテキスト）、概要・影響範囲、一次情報へのリンク（公式リリースノート、GitHub Releases、CVEなど）を必ず含める  
  - 複数ソースがある場合は複数リンクを付与し、必要に応じてサブ箇条書きで整理

### 4. 主要変更点の分類
- **Breaking Changes**（互換性破壊）- コード例付き
  - **プロジェクトへの影響度**: プロジェクトコンテキストを考慮した影響分析を追記
- **セキュリティ修正**（CVE番号、重要度、影響範囲）
  - **プロジェクトへの影響度**: セキュリティ要件の高いプロジェクトでは特に重要視
- **バグ修正**（特に重要なもの）
  - **プロジェクト関連性**: プロジェクトの重要機能に関連するバグ修正を強調
- **新機能追加**
  - **プロジェクトでの活用可能性**: プロジェクトで活用できる新機能を明示
- **パフォーマンス改善**（ベンチマーク結果があれば）
  - **プロジェクトへのメリット**: パフォーマンス重視のプロジェクトでは特に詳細に
- **廃止予定機能**（Deprecation）- 代替方法付き
  - **プロジェクトでの使用状況**: プロジェクトで該当機能を使用している可能性を評価

### 5. 影響範囲の特定
- コードへの影響（API変更、関数シグネチャ変更）
- 設定ファイルへの影響（config変更）
- 依存関係への影響（peer dependencies）
- ビルドプロセスへの影響
- 実行環境への影響（Node.jsバージョンなど）
- **クロスブラウザ互換性**（全プラットフォーム対応）
  - **デスクトップ**: Windows（Chrome、Firefox、Edge）、macOS（Chrome、Firefox、Safari、Edge）
  - **モバイル**: iOS（Safari、Chrome）、Android（Chrome、Firefox、Samsung Internet）
  - 古いブラウザバージョンでの動作（特にモバイル）

### 6. テスト戦略（優先度別）

**⚠️ プロジェクトコンテキストが指定されている場合**: プロジェクトの重要機能に特化したテストケースを追加してください。

**プロジェクト別のテスト例**:
- **Eコマースサイト**: 決済フロー、カート機能、在庫管理、注文処理のテスト
- **SaaS**: 認証フロー、API連携、データ同期、マルチテナント機能のテスト
- **社内ツール**: アクセス制御、ロール管理、データエクスポート機能のテスト
- **コンテンツサイト**: SEO、ページ速度、画像最適化、RSS/Sitemap生成のテスト

- 🔴 **高優先度テスト**（必須検証項目）
  - **一般的な検証項目**:
    - 具体的な検証手順
    - 検証コマンド例
    - 成功基準
  - **プロジェクト固有の検証項目**（コンテキストが指定されている場合）:
    - プロジェクトの重要機能に関連するテスト
    - ビジネスクリティカルな処理のテスト
    - コンプライアンス要件のテスト
  - **クロスブラウザ互換性テスト**（全プラットフォーム）
    - 📱 **モバイル**: iOS（Safari 最新版・16系以下）、Android（Chrome、Samsung Internet）
    - 💻 **デスクトップ**: Windows（Chrome、Edge、Firefox）、macOS（Safari、Chrome、Firefox）
    - 🔍 **古いバージョン**: 各ブラウザの1-2世代前のバージョン
- 🟡 **中優先度テスト**（推奨検証項目）
  - タブレット端末での動作確認（iPad、Androidタブレット）
  - レスポンシブデザインの確認（各画面サイズ）
  - タッチ操作とマウス操作の両方の確認
  - **プロジェクト固有の追加テスト**（コンテキストが指定されている場合）
- 🟢 **基本テスト**（回帰テスト等）
  - アクセシビリティテスト（各ブラウザのスクリーンリーダー対応）
  - 既存機能の回帰テスト

### 7. リスクアセスメント
- リスク項目ごとに発生確率・影響度・対応策を表形式で整理
- リスク軽減戦略
- **プロジェクト固有のリスク**（コンテキストが指定されている場合）:
  - プロジェクトのビジネス要件に関連するリスク
  - ダウンタイムの影響度
  - データ損失のリスク
  - ユーザー体験への影響
  - 売上・収益への影響（Eコマース等）
  - コンプライアンス・法規制への影響（金融・医療等）

### 8. 成功基準
- 必須条件
- 推奨条件
- KPI（測定可能な指標）
- **プロジェクト固有のKPI**（コンテキストが指定されている場合）:
  - プロジェクトの目標に合わせた成功指標
  - 例（Eコマース）: コンバージョン率、カート離脱率、決済成功率
  - 例（SaaS）: API応答時間、アップタイム、データ同期遅延
  - 例（コンテンツサイト）: Core Web Vitals、SEOランキング、ページビュー
  - 例（社内ツール）: ユーザー満足度、タスク完了時間、エラー発生率

### 9. 依存関係の既知問題（重要）
以下の観点で**推移的依存関係（依存の依存）も含めて**調査してください：
- **主要な依存モジュールのGitHub Issues**を確認（特にOpen Issues）
- 依存モジュールの3階層程度まで掘り下げて既知問題を調査
- **クロスブラウザ互換性の問題**（全プラットフォーム）
  - **モバイル**: iOS Safari（特に16系以下）、Android Chrome、Samsung Internet
  - **デスクトップ**: Windows（IE11含む旧Edge）、macOS Safari、各種ブラウザの古いバージョン
- JavaScript/CSS の互換性問題
  - 正規表現の新しい構文（negative lookbehind、named groups等）
  - CSS Grid、Flexboxの古いブラウザ対応
  - ES2015+の機能（Optional Chaining、Nullish Coalescing等）
- ポリフィルの必要性（core-js、whatwg-fetch等）
- バンドルサイズへの影響

**調査方法**:
1. GitHub で「{製品名} dependencies issues」を検索
2. 主要依存パッケージの「Issues」タブを確認
3. 以下のキーワードで絞り込み：
   - **モバイル**: 「iOS」「Android」「mobile」「Safari」「Samsung Internet」
   - **デスクトップ**: 「Windows」「macOS」「Edge」「Firefox」
   - **互換性**: 「browser compatibility」「polyfill」「transpile」
   - **エラー**: 「SyntaxError」「not supported」「not defined」

### 10. 参考情報（必須）
- 公式リリースノートURL（発行日付き）
- マイグレーションガイドURL
- セキュリティアドバイザリURL

## プロジェクトコンテキストの活用例

プロジェクトコンテキストを最大限活用するため、以下のような情報を含めることを推奨します：

### 推奨される情報
- **プロジェクトタイプ**: Eコマース、SaaS、社内ツール、コンテンツサイト、API等
- **規模**: トラフィック量、ユーザー数、データ量
- **重要機能**: ビジネスクリティカルな機能（決済、認証、データ処理等）
- **優先事項**: パフォーマンス、セキュリティ、SEO、可用性等
- **制約条件**: ダウンタイム許容度、予算、開発リソース、納期
- **技術スタック**: 主要な関連技術（フレームワーク、ライブラリ、インフラ）
- **コンプライアンス**: 業界規制、法的要件（PCI-DSS、HIPAA、GDPR等）

### 良い例
```
"Eコマースサイト、月間500万PV、年間流通額50億円、決済機能（Stripe連携）とカート機能が最重要、ダウンタイム許容度低、PCI-DSS準拠必須、Next.js + Vercel、SEOとCore Web Vitalsが重要"
```

### 避けるべき例
```
"Webサイト"  # 情報が不足
```
