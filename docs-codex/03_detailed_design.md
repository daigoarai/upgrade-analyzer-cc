# Upgrade-analyzer Codex CLI版 詳細設計書

## 1. プロンプトファイル構造

### 1.1 ファイル形式
- **ファイル名**: `prompts/upgrade-analyzer.md`
- **形式**: JSON メタ情報 + Markdown本文
- **区切り文字**: `---`（JSON メタ情報とMarkdown本文の区切り）

### 1.2 JSON メタ情報

#### 1.2.1 構造
```json
{
  "name": "upgrade-analyzer",
  "description": "ソフトウェア製品のバージョンアップ影響分析レポートを生成",
  "argument_hint": "<製品名> <バージョンFrom> <バージョンTo> [プロジェクト情報]"
}
```

#### 1.2.2 フィールド詳細

| フィールド | 型 | 必須 | 説明 |
|------------|----|----|------|
| name | string | 必須 | スラッシュコマンド名（`/prompts:upgrade-analyzer`） |
| description | string | 必須 | コマンドの説明（コマンドポップアップで表示） |
| argument_hint | string | 必須 | 引数のヒント（コマンド実行時に表示） |

#### 1.2.3 例
```json
{
  "name": "upgrade-analyzer",
  "description": "ソフトウェア製品のバージョンアップ影響分析レポートを生成",
  "argument_hint": "<製品名> <バージョンFrom> <バージョンTo> [プロジェクト情報]"
}
```

### 1.3 Markdown本文

#### 1.3.1 構造
```markdown
---
# プロンプト本文

## 1. 基本指示
- 調査対象の明確化
- 調査手順の詳細
- 出力形式の指定

## 2. 調査項目
- リリース状況確認
- 中間バージョン特定
- 段階的差分分析
- 依存関係分析
- クロスブラウザ互換性分析

## 3. レポート生成
- メタ情報生成
- 差分サマリ生成
- バージョン別変更ログ（全件・リンク付き）
- 主要変更点分類
- テスト戦略提案
- リスクアセスメント

## 4. ファイル保存
- 自動保存指示
- ファイル命名規則
- 保存場所指定
```

#### 1.3.2 引数プレースホルダー

Codex CLIでは、スラッシュコマンドの引数が順番に `{引数1}` 〜 `{引数N}` の形式でプロンプト本文へ渡される。

| プレースホルダー | 対応する値 | 説明 | 例 |
|------------------|------------|------|-----|
| `{引数1}` | 製品名 | アップグレード対象の製品名 | `Next.js` |
| `{引数2}` | バージョンFrom | 現在のバージョン | `15.4` |
| `{引数3}` | バージョンTo | アップグレード先のバージョン | `15.5.3` |
| `{引数4}` | プロジェクト情報（任意） | プロジェクトの文脈・背景・目的・特性 | `Eコマースサイト、月間100万PV` |

> 補足: プロンプト本文中では `{製品名}` や `{バージョンFrom}` といった表記も使用しているが、これらは上記の引数プレースホルダーからAIが読み替えることを意図したガイド表記であり、実際の置換は `{引数1}`〜`{引数4}` で行われる。

## 2. Web検索機能の詳細

### 2.1 Codex CLI Web検索機能の活用

#### 2.1.1 検索対象
- **公式リリースノート**: 製品の公式サイト
- **GitHub Releases**: GitHub リリースページ
- **セキュリティアドバイザリ**: セキュリティ関連情報
- **依存関係情報**: 依存パッケージの情報
- **互換性情報**: ブラウザ・プラットフォーム互換性

#### 2.1.2 検索キーワード
```
# 基本検索
"{製品名} {バージョンFrom} to {バージョンTo} changelog"
"{製品名} {バージョンFrom} to {バージョンTo} release notes"
"{製品名} {バージョンFrom} to {バージョンTo} migration guide"

# セキュリティ検索
"{製品名} {バージョンFrom} to {バージョンTo} security"
"{製品名} {バージョンFrom} to {バージョンTo} CVE"
"{製品名} {バージョンFrom} to {バージョンTo} vulnerability"

# 依存関係検索
"{製品名} {バージョンFrom} to {バージョンTo} dependencies"
"{製品名} {バージョンFrom} to {バージョンTo} breaking changes"
"{製品名} {バージョンFrom} to {バージョンTo} compatibility"

# パフォーマンス検索
"{製品名} {バージョンFrom} to {バージョンTo} performance"
"{製品名} {バージョンFrom} to {バージョンTo} benchmark"
"{製品名} {バージョンFrom} to {バージョンTo} optimization"
```

#### 2.1.3 検索手順
1. **リリース状況確認**: 指定バージョンのリリース状況を確認
2. **中間バージョン特定**: FromとToの間の全バージョンを特定
3. **段階的差分分析**: 各バージョン間の変更点を個別に調査
4. **累積影響評価**: 全変更点を統合して総合的な影響を分析

### 2.2 情報収集の優先順位

#### 2.2.1 一次情報（最優先）
- 公式リリースノート
- GitHub Releases
- セキュリティアドバイザリ
- 公式マイグレーションガイド

#### 2.2.2 二次情報（参考）
- コミュニティブログ
- 技術記事
- フォーラム情報

#### 2.2.3 避けるべき情報
- 推測情報
- 不確実な情報
- 古い情報

## 3. ファイル保存処理の詳細

### 3.1 保存場所
- **ディレクトリ**: `reports/`
- **権限**: 読み書き可能
- **作成**: 存在しない場合は自動作成

### 3.2 ファイル命名規則

#### 3.2.1 基本形式
```
{製品名}_{バージョンFrom}_to_{バージョンTo}_{YYYYMMDD}_{HHMMSS}.md
```

#### 3.2.2 命名例
```
# 基本形式
nextjs_15.4_to_15.5.3_20250128_143022.md
react_18.2.0_to_18.3.1_20250128_150315.md
postgresql_14.1_to_15.0_20250128_161045.md

# プロジェクト情報付き（オプション）
nextjs_15.4_to_15.5.3_ecommerce_20250128_143022.md
react_18.2.0_to_18.3.1_internal-tool_20250128_150315.md
```

#### 3.2.3 特殊文字の処理
- **スペース**: `_` に置換
- **特殊文字**: `-` に置換
- **日本語**: そのまま使用

### 3.3 ファイル内容

#### 3.3.1 レポート構造
```markdown
# {製品名} {バージョンFrom} → {バージョンTo} バージョンアップ影響分析レポート

## 1. メタ情報
- 調査日: {現在の日付}
- リリース状況確認: {確認結果}
- 中間バージョン一覧: {一覧}
- セマンティックバージョン分類: {分類}
- 重要度: {重要度}

## 2. 差分サマリ
- バージョン範囲: {From} → {To}
- 総変更数: {数}
- Breaking Changes数: {数}
- セキュリティ修正数: {数}
- 新機能数: {数}
- バグ修正数: {数}

## 3. バージョン別変更ログ（全件）
- From、全中間バージョン、To を含む全バージョンを古い順に並べ、`#### {バージョン番号}（リリース日: YYYY-MM-DD）` として小見出しを生成
- 各バージョン小見出しでは、そのバージョンで公開された変更点を**漏れなく列挙**し、省略は不可
  - 変更種別（Breaking / Feature / Security / Bugfix / Deprecationなど）を明示
  - 変更内容の概要と影響範囲を記載
  - 公式リリースノートやGitHub Releases、セキュリティアドバイザリ等の一次情報へのリンクを必ず付与（複数ソースがある場合は複数リンク）
- 変更件数が多い場合は箇条書きの階層化等で読みやすく整理する

## 4. 主要変更点
- Breaking Changes
- セキュリティ修正
- バグ修正
- 新機能追加
- パフォーマンス改善
- 廃止予定機能

## 5. 依存関係の既知問題
- 主要な依存モジュールのGitHub Issues
- クロスブラウザ互換性の問題
- JavaScript/CSS の互換性問題
- ポリフィルの必要性

## 6. 影響範囲の詳細分析
- コードへの影響
- 設定ファイルへの影響
- 依存関係への影響
- ビルドプロセスへの影響
- 実行環境への影響

## 7. テスト戦略・観点
- 高優先度テスト
- 中優先度テスト
- 基本テスト

## 8. リスクアセスメント
- リスク項目ごとの評価
- リスク軽減戦略

## 9. 成功基準
- 必須条件
- 推奨条件
- KPI

## 10. 推奨アクションプラン
- 実装計画
- 優先順位

## 11. 参考情報・出典
- 公式リリースノートURL
- マイグレーションガイドURL
- セキュリティアドバイザリURL
- GitHub Release URL
```

## 4. エラーハンドリング

### 4.1 入力エラー

#### 4.1.1 引数不足
- **エラー**: 必須引数が不足
- **対応**: エラーメッセージ表示、引数ヒント表示
- **メッセージ**: "必須引数が不足しています。引数: <製品名> <バージョンFrom> <バージョンTo>"

#### 4.1.2 バージョン形式エラー
- **エラー**: バージョン形式が不正
- **対応**: 警告メッセージ表示、正しい形式の例示
- **メッセージ**: "バージョン形式が不正です。例: 15.4, 18.2.0"

#### 4.1.3 製品名エラー
- **エラー**: 製品名が空または不正
- **対応**: エラーメッセージ表示
- **メッセージ**: "製品名を正しく入力してください"

### 4.2 処理エラー

#### 4.2.1 プロンプトファイルエラー
- **エラー**: プロンプトファイルが見つからない
- **対応**: エラーメッセージ表示、ファイル配置の確認
- **メッセージ**: "プロンプトファイルが見つかりません: prompts/upgrade-analyzer.md"

#### 4.2.2 JSON メタ情報エラー
- **エラー**: JSON メタ情報の解析エラー
- **対応**: エラーメッセージ表示、JSON形式の確認
- **メッセージ**: "JSON メタ情報の解析に失敗しました。形式を確認してください"

#### 4.2.3 Web検索エラー
- **エラー**: インターネット接続エラー
- **対応**: エラーメッセージ表示、接続確認の指示
- **メッセージ**: "インターネット接続を確認してください"

#### 4.2.4 ファイル保存エラー
- **エラー**: ファイル保存に失敗
- **対応**: エラーメッセージ表示、権限確認の指示
- **メッセージ**: "ファイル保存に失敗しました。権限を確認してください"

### 4.3 警告

#### 4.3.1 リリース未確認
- **警告**: 指定バージョンがリリースされていない可能性
- **対応**: 警告メッセージ表示、最新バージョンの確認
- **メッセージ**: "指定されたバージョンがリリースされていない可能性があります"

#### 4.3.2 情報不足
- **警告**: 十分な情報が収集できていない
- **対応**: 警告メッセージ表示、追加調査の推奨
- **メッセージ**: "情報が不足している可能性があります。追加調査を推奨します"
