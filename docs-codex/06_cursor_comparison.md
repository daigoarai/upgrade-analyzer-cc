## 1. 概要

### 1.1 比較の目的
- Cursor版とCodex版の機能・実装方式・使用方法の違いを明確化
- 移行時の考慮事項を整理
- 両環境での併用方法を提示

### 1.2 比較対象
- **Cursor版**: `.cursorrules` ファイルでスラッシュコマンドを定義
- **Codex版**: `prompts/<name>.md` ファイルでプロンプトを定義

## 5. メリット・デメリット比較

### 5.1 Cursor版

#### 5.1.1 メリット
- **統合性**: Cursor内で完結
- **シンプル**: 単一ファイルで管理
- **学習コスト**: 低い（既存のCursorユーザー）
- **デバッグ**: 容易（単一ファイル）

#### 5.1.2 デメリット
- **柔軟性**: 低い（プロンプトとメタ情報が混在）
- **保守性**: 低い（単一ファイルでの管理）
- **拡張性**: 低い（新しいコマンド追加が困難）
- **共有性**: 低い（プロジェクト固有）

### 5.2 Codex版

#### 5.2.1 メリット
- **柔軟性**: 高い（JSON メタ情報とプロンプト分離）
- **保守性**: 高い（専用ファイルでの管理）
- **拡張性**: 高い（新しいプロンプトファイル追加が容易）
- **共有性**: 高い（プロンプトファイルの共有が容易）
- **標準性**: 高い（Codex CLI標準形式）

#### 5.2.2 デメリット
- **複雑性**: 高い（複数ファイルでの管理）
- **学習コスト**: 高い（Codex CLIの学習が必要）
- **デバッグ**: 困難（複数ファイルでの管理）
- **依存性**: 高い（Codex CLI必須）

## 10. 移行ガイド

#### 10.1.1 移行手順
1. **Codex CLIのインストール**
   - Codex CLI最新版をインストール
   - 動作確認

2. **プロンプトファイルの作成**
   - `prompts/upgrade-analyzer.md` を作成
   - `.cursorrules` の内容を移植
   - JSON メタ情報を追加

3. **設定の移行**
   - プロンプト内容の移行
   - メタ情報の移行
   - 引数ヒントの移行

4. **動作確認**
   - Codex CLIでスラッシュコマンド実行
   - レポート生成確認
   - ファイル保存確認

#### 10.1.2 移行時の注意点
- **コマンド名の変更**: `/upgrade-analyzer` → `/prompts:upgrade-analyzer`
- **ファイル構成の変更**: `.cursorrules` → `prompts/upgrade-analyzer.md`
- **メタ情報の分離**: プロンプト内 → JSON メタ情報
- **引数ヒントの分離**: プロンプト内 → `argument_hint`

## 11. 併用方法

### 11.1 両環境での併用

#### 11.1.1 ファイル構成
```
upgrade-analyzer/
├── .cursorrules              # Cursor版設定
├── prompts/                  # Codex版設定
│   └── upgrade-analyzer.md
├── reports/                  # 共通レポート保存場所
├── docs/                     # Cursor版設計書
├── docs-codex/               # Codex版設計書
└── README.md
```

#### 11.1.2 使用方法
- **Cursor環境**: `/upgrade-analyzer` で実行
- **Codex環境**: `/prompts:upgrade-analyzer` で実行
- **レポート**: 両環境で同一の `reports/` フォルダを使用

### 11.2 同期方法

#### 11.2.1 プロンプト同期
- プロンプト内容の変更時は両ファイルを更新
- メタ情報の変更時は両ファイルを更新
- 引数ヒントの変更時は両ファイルを更新

#### 11.2.2 レポート同期
- レポートは同一の `reports/` フォルダに保存
- 両環境で同一のレポートを参照可能
- 履歴管理も共通

## 12. 推奨事項

### 12.1 環境選択

#### 12.1.1 Cursor版を推奨する場合
- 既存のCursorユーザー
- シンプルな管理を希望
- デバッグの容易さを重視
- 学習コストを最小限にしたい

#### 12.1.2 Codex版を推奨する場合
- 新しい環境での利用
- 柔軟性と拡張性を重視
- プロンプトの共有を重視
- 標準的な形式を重視

### 12.2 移行タイミング

#### 12.2.1 移行を検討する場合
- 新しいプロジェクトの開始時
- 既存プロジェクトの大幅な変更時
- チームでの利用開始時
- プロンプトの共有が必要になった時

#### 12.2.2 移行を避ける場合
- 既存のワークフローが確立されている
- 緊急の対応が必要
- 学習コストを避けたい
- 現在の環境で問題がない
