# バージョンアップ影響調査プロンプトテンプレート

## ⚠️ 必須前提条件

このプロンプトテンプレートは、**Cursor最新版 + Browser機能ON** での使用を前提としています。

### 事前準備チェックリスト

- [ ] **Cursorを最新版にアップデート済み**
- [ ] **Browser機能がON** になっている（設定で確認）
- [ ] **チャット欄の「＋Browser」がON** になっている
- [ ] バージョンアップ対象の製品名とバージョン番号を把握済み

> ⚡ **重要**: Browser機能により、AIが公式リリースノート・GitHub・セキュリティアドバイザリなどをリアルタイムで検索し、最新の一次情報に基づいた分析を提供します。

## 使い方

### Step 1: 下記の「📋 調査プロンプト（ここからコピー）」から「（ここまでコピー）」までをコピー

**それ以外の本文は変更不要です。** AIが自動的に変数を参照して解釈します。

### Step 3: Cursorのチャットに貼り付けて実行

```

**🚀 重要**: 以下の手順で網羅的な調査を実施してください：

1. **リリース状況の確認**:
   - まず、対象製品の最新リリース状況を確認
   - 指定されたバージョンが実際にリリースされているか検証
   - リリースされていない場合は、最新の利用可能バージョンを特定

2. **バージョン差分の網羅的調査**:

3. **一次情報の優先**:
   - 公式リリースノートを最優先で調査
   - GitHub Releases、公式ブログ、セキュリティアドバイザリを確認
   - 推測や不確実な情報は避け、事実に基づいた分析のみを提供

## 調査対象

上記の製品について、バージョンFrom から バージョンTo へのバージョンアップを予定しています。

**⚠️ 必須調査手順**:
1. **リリース状況の検証**: 指定されたバージョンが実際にリリースされているか確認
2. **中間バージョンの特定**: FromとToの間にある全バージョンを特定
3. **段階的差分分析**: 各バージョン間の変更点を個別に調査
4. **累積影響の評価**: 全変更点を統合して総合的な影響を分析

差分を明確にして、テストする観点を整理して下さい。

## 調査項目

以下の観点で網羅的に調査してください：

### 1. メタ情報
- **調査日**: 現在の日付を動的に取得（YYYY-MM-DD形式）
- セマンティックバージョン分類（MAJOR/MINOR/PATCH）
- 重要度（高/中/低）

### 2. バージョン別変更ログ（全件）
- From、全中間バージョン、To を含む**すべてのバージョン**を古い順に並べ、`#### {バージョン番号}（リリース日: YYYY-MM-DD）` の小見出しを作成
- 各バージョン小見出しでは、そのバージョンで生じた**全変更項目**（Breaking / Feature / Security / Bugfix / Deprecation など）を漏れなく列挙する
  - 各行に変更種別（絵文字やテキスト）、変更概要と影響範囲、一次情報（公式リリースノート、GitHub Releases、セキュリティアドバイザリ等）へのリンクを必ず含める
  - 一つの変更に複数ソースがある場合は、主要なリンクをすべて併記し、必要に応じてサブ箇条書きで整理する

### 3. 主要変更点の分類
- **Breaking Changes**（互換性破壊）- コード例付き
- **セキュリティ修正**（CVE番号、重要度、影響範囲）
- **バグ修正**（特に重要なもの）
- **新機能追加**
- **パフォーマンス改善**（ベンチマーク結果があれば）
- **廃止予定機能**（Deprecation）- 代替方法付き

### 4. 影響範囲の特定
- コードへの影響（API変更、関数シグネチャ変更）
- 設定ファイルへの影響（config変更）
- 依存関係への影響（peer dependencies）
- ビルドプロセスへの影響
- 実行環境への影響（Node.jsバージョンなど）
- **クロスブラウザ互換性**（全プラットフォーム対応）
  - **デスクトップ**: Windows（Chrome、Firefox、Edge）、macOS（Chrome、Firefox、Safari、Edge）
  - **モバイル**: iOS（Safari、Chrome）、Android（Chrome、Firefox、Samsung Internet）
  - 古いブラウザバージョンでの動作（特にモバイル）

### 5. テスト戦略（優先度別）
- 🔴 **高優先度テスト**（必須検証項目）
  - 具体的な検証手順
  - 検証コマンド例
  - 成功基準
  - **クロスブラウザ互換性テスト**（全プラットフォーム）
    - 📱 **モバイル**: iOS（Safari 最新版・16系以下）、Android（Chrome、Samsung Internet）
    - 💻 **デスクトップ**: Windows（Chrome、Edge、Firefox）、macOS（Safari、Chrome、Firefox）
    - 🔍 **古いバージョン**: 各ブラウザの1-2世代前のバージョン
- 🟡 **中優先度テスト**（推奨検証項目）
  - タブレット端末での動作確認（iPad、Androidタブレット）
  - レスポンシブデザインの確認（各画面サイズ）
  - タッチ操作とマウス操作の両方の確認
- 🟢 **基本テスト**（回帰テスト等）
  - アクセシビリティテスト（各ブラウザのスクリーンリーダー対応）

### 6. リスクアセスメント
- リスク項目ごとに発生確率・影響度・対応策を表形式で整理
- リスク軽減戦略

### 7. 成功基準
- 必須条件
- 推奨条件
- KPI（測定可能な指標）

### 8. 依存関係の既知問題（重要）
以下の観点で**推移的依存関係（依存の依存）も含めて**調査してください：

#### 8.1 主要依存関係の調査
- **React/React DOM**: バージョン互換性、新機能の影響
- **TypeScript**: 型定義の変更、コンパイルエラー
- **Node.js**: ランタイム互換性、API変更
- **Webpack/Vite**: ビルドツールの互換性
- **ESLint/Prettier**: リンター・フォーマッターの互換性

#### 8.2 推移的依存関係の深掘り調査
- **主要な依存モジュールのGitHub Issues**を確認（特にOpen Issues）
- 依存モジュールの3階層程度まで掘り下げて既知問題を調査
- **npm/yarn audit**でセキュリティ脆弱性を確認

#### 8.3 クロスブラウザ互換性の問題（全プラットフォーム）
**📱 モバイル**:
- **iOS Safari**: 16.3以下での正規表現エラー（negative lookbehind非対応）
- **Android Chrome**: 古いバージョンでのES2015+機能非対応
- **Samsung Internet**: 独自実装による互換性問題

**💻 デスクトップ**:
- **Windows Edge（旧版）**: CSS Grid Layoutの部分的サポート
- **macOS Safari**: 古いバージョンでのJavaScript機能制限
- **Firefox**: 独自実装による動作差異

#### 8.4 JavaScript/CSS の互換性問題
- **正規表現**: negative lookbehind、named groups等の新構文
- **CSS**: Grid Layout、Flexboxの古いブラウザ対応
- **ES2015+**: Optional Chaining、Nullish Coalescing等
- **ポリフィル**: core-js、whatwg-fetch等の必要性

#### 8.5 具体的な調査方法
**検索キーワード**:
- `"{製品名} dependencies issues"`
- `"{製品名} browser compatibility"`
- `"{製品名} mobile safari issues"`
- `"{製品名} edge compatibility"`
- `"{製品名} polyfill required"`

**GitHub Issues検索**:
- 主要依存パッケージの「Issues」タブを確認
- 以下のキーワードで絞り込み：
  - **モバイル**: 「iOS」「Android」「mobile」「Safari」「Samsung Internet」
  - **デスクトップ**: 「Windows」「macOS」「Edge」「Firefox」
  - **互換性**: 「browser compatibility」「polyfill」「transpile」
  - **エラー**: 「SyntaxError」「not supported」「not defined」

**具体的な問題例**:
- `mdast-util-gfm-autolink-literal@2.0.1` - iOS Safari 16.3以下で正規表現エラー
- `css-grid-polyfill` - Windows Edge 18以下でCSS Grid表示崩れ
- `core-js@3.x` - 古いブラウザでのES2015+機能非対応

**⚠️ 重要**: 調査結果を以下の形式の**Markdownファイルとして出力**してください。

### ファイル形式

```markdown
# {製品名} {バージョンFrom} → {バージョンTo} バージョンアップ影響分析レポート

## メタ情報

|------|------|

```

### 必須要素

1. **視覚的な整理**: 表形式、絵文字（🔴🟡🟢⚠️🚀📊等）を活用
2. **具体性**: コマンド例、コードスニペット、URL、日付を必ず含める
3. **優先度明示**: 重要度が一目でわかるように（🔴高🟡中🟢低）
4. **実行可能**: すぐにテスト・実装に移れるレベルの具体性
5. **出典明記**: すべての情報源にURLと発行日を記載
6. **コピー可能**: コードブロックには言語指定（bash, typescript等）

### レポート構成

以下のセクションを含めてください：

1. **メタ情報**（表形式）
   - **調査日**: 現在の日付を動的に取得（YYYY-MM-DD形式）
2. 差分サマリ
3. 主要変更点（分類別）
4. **依存関係の既知問題**（⚠️**全プラットフォームのブラウザ互換性**含む）
   - **具体的な問題例を必ず含める**:
     - `mdast-util-gfm-autolink-literal@2.0.1` - iOS Safari 16.3以下で正規表現エラー
     - `css-grid-polyfill` - Windows Edge 18以下でCSS Grid表示崩れ
     - `core-js@3.x` - 古いブラウザでのES2015+機能非対応
   - Windows、macOS、iOS、Androidの各ブラウザでの問題を明記
   - モバイルとデスクトップを区別して記載
5. テスト戦略・観点（優先度別・プラットフォーム別）
   - クロスブラウザテストマトリクス
6. リスクアセスメント（表形式）
7. 成功基準とKPI（ブラウザ別のエラー率含む）
8. 参考情報・出典（Can I Useなどの互換性情報含む）

## ❓ よくある質問

### Q1: プロンプトが長すぎて、どこからコピーすればいいかわからない

**A**: **「📋 調査プロンプト（ここからコピー）」** の直後の ``` から、**「（ここまでコピー）」** の直前の ``` までをコピーしてください。

### Q2: Browser機能がない場合は？

**A**: Cursor を最新版にアップデートしてください。それでもない場合は、手動で公式サイトを確認する必要があります。

### Q3: 調査結果の精度が低い場合は？

**A**: 以下を試してください：
- プロンプトに具体的なバージョン番号を明記
- 「公式リリースノートを必ず確認してください」と追記
- 特定の関心事項を明記（例：セキュリティ、パフォーマンス等）

### Q4: 複数バージョンまたぐアップグレード（例: 14 → 18）の場合は？

**A**: 段階的に調査することを推奨します：
1. まず 14 → 15, 15 → 16, 16 → 17, 17 → 18 を個別に調査
2. その後、全体の影響をまとめる
3. または、プロンプトに「中間バージョンも含めて調査」と明記

### Q5: 依存モジュールの既知問題はどこまで調査すべきですか？

**A**: 以下のガイドラインを推奨します：
- **直接依存**: すべて確認（package.jsonに記載されているもの）
- **推移的依存**: 主要なもの（3階層程度まで）
- **特に注意**: ブラウザで実行されるコード（フロントエンド関連）
- **検索例**:
  ```
  「Next.js dependencies browser compatibility iOS」
  「{製品名} GitHub issues Safari」
  ```

### Q6: クロスブラウザ互換性の問題を防ぐには？

**A**: 以下を事前確認：

**プロンプトへの明記**:
- 対象プラットフォーム（Windows/macOS/iOS/Android）を明記
- サポート対象のブラウザバージョンを明記
  - 例: 「iOS 16.3以上」「Chrome 最新版含む2世代」
- 重点確認ブラウザを指定
  - モバイルファースト: 「iOS Safari、Android Chrome優先」
  - デスクトップ重視: 「Windows Chrome、macOS Safari優先」

**技術的な確認事項**:
- JavaScript の新しい構文（正規表現lookbehind、Optional Chaining等）
- CSS の新機能（Grid、カスタムプロパティ等）
- Web API の対応状況（Fetch、Intersection Observer等）
- ポリフィルの必要性（core-js、whatwg-fetch等）

**確認ツール**:
- [Can I Use](https://caniuse.com/) で機能別の対応状況確認
- [MDN Browser Compatibility](https://developer.mozilla.org/) でAPI対応確認
- BrowserStack、LambdaTest等で実機テスト
