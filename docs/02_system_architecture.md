# Upgrade-analyzer システムアーキテクチャ

## 1. システム概要

### 1.1 アーキテクチャの特徴
- **プロンプトベース**: プログラミング言語を使用せず、プロンプトテンプレートでAIに分析を実行
- **Cursor依存**: Cursorのスラッシュコマンド機能とBrowser機能を活用
- **ファイルベース**: データベースを使用せず、ファイルシステムでデータを管理
- **テンプレート駆動**: プロンプトとレポートのテンプレートで動作を制御

## 2. システム構成

### 2.1 主要コンポーネント

#### 2.1.1 Cursor IDE
- **役割**: ユーザーインターフェース、スラッシュコマンド実行環境
- **機能**: 
  - スラッシュコマンド `/upgrade-analyzer` の認識
  - Browser機能によるWeb検索
  - AIとの対話

#### 2.1.2 プロンプトテンプレート
- **ファイル**: `templates/prompt_template.md`
- **役割**: AIに実行させる分析指示を定義
- **機能**:
  - 変数置換（製品名、バージョン等）
  - 分析手順の定義
  - 出力形式の指定

#### 2.1.3 レポートテンプレート
- **ファイル**: `templates/report_template.md`
- **役割**: レポートの構造とフォーマットを定義
- **機能**:
  - Markdown形式のレポート構造
  - セクションの定義
  - 表形式のテンプレート

#### 2.1.4 AI分析エンジン
- **実装**: Cursor内蔵のAI機能
- **役割**: プロンプトに基づいて分析を実行
- **機能**:
  - Web検索による情報収集
  - 情報の分析・分類
  - レポートの生成

#### 2.1.5 ファイル管理システム
- **実装**: ファイルシステム
- **役割**: レポートの保存と管理
- **機能**:
  - レポートファイルの保存
  - タイムスタンプ付きファイル名生成
  - ディレクトリ管理

### 2.2 データフロー

```
1. ユーザー入力
   ↓
2. スラッシュコマンド実行
   ↓
3. プロンプトテンプレート読み込み
   ↓
4. 変数置換
   ↓
5. AI分析実行
   ↓
6. Browser機能でWeb検索
   ↓
7. 情報収集・分析
   ↓
8. レポート生成
   ↓
9. ファイル保存
   ↓
10. 結果表示
```

## 3. 技術スタック

### 3.1 必須技術
- **Cursor IDE**: 最新版（スラッシュコマンド、Browser機能）
- **Markdown**: レポート形式
- **ファイルシステム**: データ保存

### 3.2 使用しない技術
- **プログラミング言語**: 使用しない（プロンプトのみ）
- **データベース**: 使用しない（ファイルベース）
- **外部API**: 使用しない（Browser機能のみ）
- **Webサーバー**: 使用しない（ローカル実行）

## 4. ファイル構成

### 4.1 ディレクトリ構造
```
upgrade-analyzer/
├── .cursorrules              # スラッシュコマンド定義
├── README.md                 # プロジェクト説明
├── templates/
│   ├── prompt_template.md    # プロンプトテンプレート
│   └── report_template.md    # レポートテンプレート
├── reports/                  # 生成されたレポート保存場所
├── examples/                 # 実例レポート
```

### 4.2 ファイルの役割

#### 4.2.1 `.cursorrules`
- スラッシュコマンド `/upgrade-analyzer` の定義
- プロンプトの実行指示
- ファイル保存の指示

#### 4.2.2 `templates/prompt_template.md`
- AIに実行させる分析プロンプト
- 変数置換のためのプレースホルダー
- 分析手順の詳細指示

#### 4.2.3 `templates/report_template.md`
- レポートの構造テンプレート
- Markdown形式のセクション定義
- 表形式のテンプレート

#### 4.2.4 `reports/`
- 生成されたレポートの保存場所
- タイムスタンプ付きファイル名
- 履歴管理

## 5. 処理フロー

### 5.1 メイン処理フロー

#### 5.1.1 初期化
1. スラッシュコマンド `/upgrade-analyzer` の認識
2. 引数の解析（製品名、バージョン、プロジェクト情報）
3. プロンプトテンプレートの読み込み

#### 5.1.2 分析実行
1. プロンプトテンプレートの変数置換
2. AI分析エンジンへのプロンプト送信
3. Browser機能によるWeb検索実行
4. 情報収集・分析の実行

#### 5.1.3 レポート生成
1. 分析結果の整理
2. レポートテンプレートの適用
3. Markdown形式でのレポート生成
4. ファイル保存の実行

#### 5.1.4 完了
1. 保存されたファイルパスの表示
2. 処理完了の確認

### 5.2 エラーハンドリング

#### 5.2.1 入力エラー
- 引数不足の場合のエラーメッセージ
- バージョン形式の不正な場合の警告

#### 5.2.2 処理エラー
- Browser機能が無効な場合のエラー
- インターネット接続エラーの処理
- ファイル保存エラーの処理

## 6. セキュリティ考慮事項

### 6.1 データ保護
- ローカルファイル保存のみ
- 外部へのデータ送信なし
- 個人情報の収集なし

### 6.2 情報源の信頼性
- 公式情報の優先使用
- 一次情報の重視
- 推測情報の排除

### 6.3 アクセス制御
- ローカルファイルシステムの権限
- レポートファイルの読み取り権限

## 7. パフォーマンス考慮事項

### 7.1 処理時間
- レポート生成: 5分以内
- ファイル保存: 10秒以内
- Web検索: リアルタイム

### 7.2 リソース使用量
- CPU: CursorのAI処理
- メモリ: レポート生成時
- ディスク: レポートファイル保存

### 7.3 スケーラビリティ
- 同時実行: 1ユーザー
- レポート数: ファイルシステムの制限
- 履歴管理: 手動削除

## 8. 保守性考慮事項

### 8.1 プロンプト管理

### 8.2 テンプレート管理

### 8.3 設定管理
