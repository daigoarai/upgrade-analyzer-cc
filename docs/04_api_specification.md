# Upgrade-analyzer API仕様書

## 1. 概要

### 1.1 仕様の目的
Upgrade-analyzerのAPI仕様を定義し、開発・運用・保守の指針を提供する。

### 1.2 仕様の範囲
- スラッシュコマンドAPI
- プロンプトテンプレートAPI
- ファイル管理API
- エラーハンドリングAPI

### 1.3 注意事項
**重要**: このツールは従来のAPI（REST API、GraphQL等）を使用せず、Cursorのスラッシュコマンド機能とプロンプトテンプレートを使用します。

## 2. スラッシュコマンドAPI

### 2.1 コマンド仕様

#### 2.1.1 基本コマンド
```text
/upgrade-analyzer <製品名> <バージョンFrom> <バージョンTo> [プロジェクト情報]
```

#### 2.1.2 パラメータ仕様

| パラメータ | 型 | 必須 | 説明 | 例 |
|-----------|----|----|------|-----|
| 製品名 | string | 必須 | バージョンアップ対象の製品名 | "Next.js", "React", "PostgreSQL" |
| バージョンFrom | string | 必須 | 現在のバージョン | "15.4", "18.2.0", "14.1" |
| バージョンTo | string | 必須 | アップグレード先のバージョン | "15.5.3", "18.3.1", "15.0" |
| プロジェクト情報 | string | オプション | プロジェクトの特性・要件 | "Eコマースサイト、月間100万PV" |

#### 2.1.3 使用例
```text
# 基本的な使用方法
/upgrade-analyzer Next.js 15.4 15.5.3

# プロジェクト情報を含めた使用方法
/upgrade-analyzer Next.js 15.4 15.5.3 "Eコマースサイト、月間100万PV、決済機能とカート機能が重要、SEOとパフォーマンスが最優先"

# 複数バージョンの分析
/upgrade-analyzer React 18.2.0 18.3.1 "社内の勤怠管理システム、認証とアクセス制御が重要、ダウンタイム許容度低"
```

### 2.2 レスポンス仕様

#### 2.2.1 成功レスポンス
```markdown
## ✅ レポート生成完了

**ファイル名**: `reports/nextjs_15.4_to_15.5.3_20250128_143022.md`
**保存場所**: `/Users/username/upgrade-analyzer/reports/`
**生成時間**: 2分30秒
**レポートサイズ**: 15.2KB

### 生成されたレポートの概要
- メタ情報: 調査日、リリース状況、中間バージョン一覧
- 差分サマリ: 総変更数、Breaking Changes数、セキュリティ修正数
- 主要変更点: 分類別の詳細な変更内容
- 依存関係の既知問題: ブラウザ互換性を含む既知の問題
- テスト戦略: 優先度別・プラットフォーム別のテスト観点
- リスクアセスメント: リスク項目と対応策
- 成功基準とKPI: 測定可能な指標

### 次のステップ
1. 生成されたレポートを確認
2. プロジェクト固有の検証を実施
3. テスト計画を策定
4. 段階的なアップグレードを実施
```

#### 2.2.2 エラーレスポンス
```markdown
## ❌ エラーが発生しました

**エラーコード**: E001
**エラーメッセージ**: 引数が不足しています
**解決方法**: 以下の形式でコマンドを実行してください

```
/upgrade-analyzer <製品名> <バージョンFrom> <バージョンTo>
```

**詳細**: 製品名、現在のバージョン、アップグレード先のバージョンをすべて指定してください。
```

### 2.3 エラーコード一覧

| エラーコード | エラーメッセージ | 原因 | 解決方法 |
|-------------|-----------------|------|----------|
| E001 | 引数が不足しています | 必要な引数が指定されていない | 必要な引数をすべて指定してください |
| E002 | バージョン形式が正しくありません | バージョン番号の形式が無効 | 正しいバージョン形式で入力してください |
| E003 | 製品名が正しくありません | 製品名が無効または空 | 有効な製品名を入力してください |
| E004 | Browser機能が無効です | CursorのBrowser機能が無効 | Cursor設定でBrowser機能を有効にしてください |
| E005 | インターネット接続エラー | インターネット接続に問題 | インターネット接続を確認してください |
| E006 | AI処理でエラーが発生しました | AI処理中にエラーが発生 | しばらく待ってから再実行してください |
| E007 | ファイル保存に失敗しました | ファイルの書き込みに失敗 | ファイル権限を確認してください |
| E008 | ディレクトリ作成に失敗しました | ディレクトリの作成に失敗 | ディレクトリ権限を確認してください |
| E009 | ファイルアクセス権限がありません | ファイルへのアクセス権限がない | ファイル権限を確認してください |

### 3.2 プロンプト構造

#### 3.2.1 ヘッダー部分
```markdown
# バージョンアップ影響調査プロンプトテンプレート

## ⚠️ 必須前提条件
このプロンプトテンプレートは、**Cursor最新版 + Browser機能ON** での使用を前提としています。

### 事前準備チェックリスト
- [ ] **Cursorを最新版にアップデート済み**
- [ ] **Browser機能がON** になっている（Settings → Tools & Integrations → Browser Automationで確認）
- [ ] **チャット欄の「＋Browser」がON** になっている
- [ ] バージョンアップ対象の製品名とバージョン番号を把握済み
```

#### 3.2.2 メインプロンプト部分
```markdown
あなたは、ソフトウェアのバージョンアップ影響分析の専門家です。
公式リリースノート、GitHub、セキュリティアドバイザリなどの一次情報をBrowser機能で調査し、正確で実用的なレポートを作成してください。

**🚀 重要**: 以下の手順で網羅的な調査を実施してください：

1. **リリース状況の確認**:
   - まず、対象製品の最新リリース状況を確認
   - 指定されたバージョンが実際にリリースされているか検証
   - リリースされていない場合は、最新の利用可能バージョンを特定

2. **バージョン差分の網羅的調査**:
   - FromバージョンからToバージョンまでの**全中間バージョン**を特定
   - 各バージョンのリリースノートを個別に調査
   - 累積的な変更点を整理し、段階的な影響を分析

3. **一次情報の優先**:
   - 公式リリースノートを最優先で調査
   - GitHub Releases、公式ブログ、セキュリティアドバイザリを確認
   - 推測や不確実な情報は避け、事実に基づいた分析のみを提供
```

### 3.3 分析手順仕様

#### 3.3.1 必須調査手順
```markdown
**⚠️ 必須調査手順**:
1. **リリース状況の検証**: 指定されたバージョンが実際にリリースされているか確認
2. **中間バージョンの特定**: FromとToの間にある全バージョンを特定
3. **段階的差分分析**: 各バージョン間の変更点を個別に調査
4. **累積影響の評価**: 全変更点を統合して総合的な影響を分析
```

#### 3.3.2 調査項目仕様
```markdown
## 調査項目

以下の観点で網羅的に調査してください：

### 1. メタ情報
- **調査日**: 現在の日付を動的に取得（YYYY-MM-DD形式）
- **リリース状況確認**: 指定バージョンのリリース状況（リリース済み/未リリース/最新バージョン）
- **中間バージョン一覧**: FromとToの間にある全バージョンのリスト
- **セマンティックバージョン分類**: MAJOR/MINOR/PATCHの判定
- **重要度**: 高/中/低（プロジェクトコンテキストを考慮）

### 2. 差分サマリ
- **バージョン範囲**: From → To の全バージョン
- **総変更数**: 全バージョンでの累積変更数
- **Breaking Changes数**: 互換性破壊の変更数
- **セキュリティ修正数**: CVE修正の数
- **新機能数**: 追加された機能の数
- **バグ修正数**: 修正されたバグの数
```

### 4.2 セクション詳細仕様

#### 4.2.1 メタ情報セクション
- **目的**: レポートの基本情報を提供
- **形式**: 表形式（Markdown Table）
- **必須項目**: 調査日、製品名、バージョン情報、重要度

#### 4.2.2 差分サマリセクション
- **目的**: 変更の概要を一目で把握
- **形式**: 表形式（Markdown Table）
- **必須項目**: バージョン範囲、変更数、重要度

#### 4.2.3 主要変更点セクション
- **目的**: 詳細な変更内容を分類して提示
- **分類**: Breaking Changes、セキュリティ修正、バグ修正、新機能追加、パフォーマンス改善、廃止予定機能
- **形式**: セクション別の詳細説明

#### 4.2.4 依存関係の既知問題セクション
- **目的**: 推移的依存関係の問題を明示
- **形式**: 問題別の詳細説明
- **必須項目**: 問題内容、影響範囲、対応方法

#### 4.2.5 テスト戦略セクション
- **目的**: 実践的なテスト観点を提供
- **分類**: 高優先度、中優先度、基本テスト
- **形式**: 優先度別のテスト項目

#### 4.2.6 リスクアセスメントセクション
- **目的**: リスクの評価と対応策を提示
- **形式**: 表形式（Markdown Table）
- **必須項目**: リスク項目、発生確率、影響度、対応策

## 6. エラーハンドリングAPI

### 6.1 エラー分類

#### 6.1.1 入力エラー
- **E001**: 引数不足エラー
- **E002**: バージョン形式エラー
- **E003**: 製品名不正エラー

#### 6.1.2 処理エラー
- **E004**: Browser機能無効エラー
- **E005**: インターネット接続エラー
- **E006**: AI処理エラー

#### 6.1.3 ファイルエラー
- **E007**: ファイル保存エラー
- **E008**: ディレクトリ作成エラー
- **E009**: 権限エラー

### 6.2 エラーレスポンス仕様

#### 6.2.1 エラーメッセージ形式
```markdown
## ❌ エラーが発生しました

**エラーコード**: {エラーコード}
**エラーメッセージ**: {エラーメッセージ}
**解決方法**: {解決方法}

**詳細**: {詳細説明}
```

#### 6.2.2 エラーメッセージ例
```markdown
## ❌ エラーが発生しました

**エラーコード**: E001
**エラーメッセージ**: 引数が不足しています
**解決方法**: 以下の形式でコマンドを実行してください

```
/upgrade-analyzer <製品名> <バージョンFrom> <バージョンTo>
```

**詳細**: 製品名、現在のバージョン、アップグレード先のバージョンをすべて指定してください。
```

### 6.3 エラー回復仕様

#### 6.3.1 自動回復
- **条件**: 一時的なエラーの場合
- **方法**: 自動的にリトライ
- **回数**: 3回まで
- **間隔**: 指数バックオフ

#### 6.3.2 手動回復
- **条件**: 永続的なエラーの場合
- **方法**: ユーザーにエラーメッセージと解決方法を提示
- **確認**: 必要に応じて設定の確認を促す
- **再実行**: 再実行の指示

## 10. セキュリティ仕様

### 10.1 データ保護

#### 10.1.1 データ保存
- **場所**: ローカルファイルシステムのみ
- **暗号化**: なし（ローカル保存のため）
- **アクセス制御**: ファイルシステムの権限

#### 10.1.2 データ送信
- **外部送信**: なし
- **ネットワーク**: Browser機能によるWeb検索のみ
- **個人情報**: 収集・保存なし

### 10.2 情報源の信頼性

#### 10.2.1 信頼できるソース
- **公式リリースノート**: 最優先
- **GitHub Releases**: 公式情報
- **セキュリティアドバイザリ**: 公式情報

#### 10.2.2 情報の検証
- **一次情報の優先**: 推測情報の排除
- **出典の明記**: すべての情報にURL・日付を記載
- **事実の確認**: 公式情報の確認

### 10.3 アクセス制御

#### 10.3.1 ファイルアクセス
- **読み取り権限**: テンプレートファイルの読み取り
- **書き込み権限**: レポートファイルの書き込み
- **実行権限**: スラッシュコマンドの実行

#### 10.3.2 ディレクトリアクセス
- **読み取り権限**: テンプレートディレクトリの読み取り
- **書き込み権限**: レポートディレクトリの書き込み
- **作成権限**: 必要に応じてディレクトリの作成
