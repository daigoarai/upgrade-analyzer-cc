# Upgrade-analyzer 要件定義書

## 1. プロジェクト概要

### 1.1 プロジェクト名
Upgrade-analyzer

### 1.2 プロジェクトの目的
ソフトウェアのバージョンアップ時の影響分析を自動化し、開発チームが安全かつ効率的にアップグレードを実施できるよう支援するツールを提供する。

### 1.3 プロジェクトの背景
- ソフトウェアのバージョンアップは頻繁に発生するが、影響範囲の調査に時間がかかる
- 手動での調査では見落としが発生しやすく、インシデントのリスクが高い
- チーム間での調査結果の共有が困難
- 調査の標準化と効率化が求められている

### 1.4 プロジェクトの範囲
- ソフトウェアライブラリ・フレームワークのバージョンアップ影響分析
- 公式リリースノート、GitHub、セキュリティアドバイザリからの情報収集
- 包括的なレポート生成とテスト戦略の提案
- チーム内での知見共有とナレッジベース化

## 2. 機能要件

### 2.1 基本機能

#### 2.1.1 スラッシュコマンド実行
- **機能ID**: F001
- **機能名**: スラッシュコマンド実行
- **概要**: Cursorのスラッシュコマンド `/upgrade-analyzer` でバージョンアップ影響分析を実行
- **入力**: 製品名、現在のバージョン、アップグレード先のバージョン、プロジェクト情報（オプション）
- **出力**: 影響分析レポート（Markdown形式）
- **優先度**: 高

#### 2.1.2 プロンプトベース分析
- **機能ID**: F002
- **機能名**: プロンプトベース分析
- **概要**: 定義されたプロンプトテンプレートを使用してAIに分析を実行させる
- **入力**: プロンプトテンプレート、変数設定
- **出力**: AIによる分析結果
- **優先度**: 高

#### 2.1.3 Browser機能活用
- **機能ID**: F003
- **機能名**: Browser機能活用
- **概要**: CursorのBrowser機能を使用してWeb検索を実行し、公式情報を収集
- **入力**: 検索キーワード、対象URL
- **出力**: 収集したWeb情報
- **優先度**: 高

#### 2.1.4 レポート生成
- **機能ID**: F004
- **機能名**: レポート生成
- **概要**: 収集した情報を基に包括的なMarkdownレポートを生成
- **入力**: 収集した情報、レポートテンプレート
- **出力**: Markdown形式のレポート
- **優先度**: 高

#### 2.1.5 自動ファイル保存
- **機能ID**: F005
- **機能名**: 自動ファイル保存
- **概要**: 生成されたレポートを `reports/` フォルダにタイムスタンプ付きで自動保存
- **入力**: 生成されたレポート
- **出力**: 保存されたファイル
- **優先度**: 高

### 2.2 分析機能

#### 2.2.1 リリース状況確認
- **機能ID**: F006
- **機能名**: リリース状況確認
- **概要**: 指定されたバージョンが実際にリリースされているかを確認
- **入力**: 製品名、バージョン情報
- **出力**: リリース状況の確認結果
- **優先度**: 高

#### 2.2.2 中間バージョン特定
- **機能ID**: F007
- **機能名**: 中間バージョン特定
- **概要**: FromバージョンからToバージョンまでの全中間バージョンを特定
- **入力**: Fromバージョン、Toバージョン
- **出力**: 中間バージョン一覧
- **優先度**: 高

#### 2.2.3 段階的差分分析
- **機能ID**: F008
- **機能名**: 段階的差分分析
- **概要**: 各バージョン間の変更点を個別に調査し、累積的な影響を分析
- **入力**: バージョン情報、リリースノート
- **出力**: 段階的な変更点分析
- **優先度**: 高

#### 2.2.4 依存関係分析
- **機能ID**: F009
- **機能名**: 依存関係分析
- **概要**: 推移的依存関係（依存の依存）の既知問題を調査
- **入力**: 製品名、バージョン情報
- **出力**: 依存関係の既知問題リスト
- **優先度**: 中

#### 2.2.5 クロスブラウザ互換性分析
- **機能ID**: F010
- **機能名**: クロスブラウザ互換性分析
- **概要**: 全プラットフォーム（Windows/macOS/iOS/Android）での互換性を分析
- **入力**: 製品名、バージョン情報
- **出力**: プラットフォーム別互換性情報
- **優先度**: 中

### 2.3 レポート機能

#### 2.3.1 メタ情報生成
- **機能ID**: F011
- **機能名**: メタ情報生成
- **概要**: 調査日、リリース状況、中間バージョン一覧などのメタ情報を生成
- **入力**: 調査結果
- **出力**: メタ情報テーブル
- **優先度**: 高

#### 2.3.2 差分サマリ生成
- **機能ID**: F012
- **機能名**: 差分サマリ生成
- **概要**: 全バージョンでの累積変更数をまとめたサマリを生成
- **入力**: 変更点分析結果
- **出力**: 差分サマリテーブル
- **優先度**: 高

#### 2.3.3 主要変更点分類
- **機能ID**: F013
- **機能名**: 主要変更点分類
- **概要**: Breaking Changes、セキュリティ修正、バグ修正、新機能追加を分類
- **入力**: 変更点分析結果
- **出力**: 分類された変更点リスト
- **優先度**: 高

#### 2.3.4 テスト戦略提案
- **機能ID**: F014
- **機能名**: テスト戦略提案
- **概要**: 優先度別・プラットフォーム別のテスト観点を提案
- **入力**: 影響分析結果
- **出力**: テスト戦略レポート
- **優先度**: 高

#### 2.3.5 リスクアセスメント
- **機能ID**: F015
- **機能名**: リスクアセスメント
- **概要**: リスク項目ごとに発生確率・影響度・対応策を評価
- **入力**: 影響分析結果
- **出力**: リスクアセスメントテーブル
- **優先度**: 高

## 4. 制約事項

### 4.1 技術的制約
- Cursor最新版 + Browser機能が必須
- 外部APIは使用しない（Browser機能のみ）
- データベースは使用しない
- プログラミング言語は使用しない（プロンプトのみ）

### 4.2 業務的制約
- 既存の業務プロセスを大きく変更できない
- ユーザーの学習コストを最小限に抑える必要がある
- コストを抑えた実装が必要

### 4.3 法的制約
- 免責事項の明記が必要
- サポートツールとしての位置づけを明確化

## 5. 品質要件

### 5.1 機能品質
- 正確性: 公式情報に基づく正確な分析
- 完全性: 必要な情報を漏れなく提供
- 一貫性: 分析結果の一貫性を保証

### 5.2 非機能品質
- 使いやすさ: スラッシュコマンドによる直感的な操作
- 信頼性: 安定したレポート生成
- 効率性: 適切な処理時間

- レポートの品質に対する期待値の不一致

### 11.3 スケジュールリスク

- テンプレートの改善に時間がかかる
