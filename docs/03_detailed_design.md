# Upgrade-analyzer 詳細設計書

## 1. 概要

### 1.1 設計の目的
Upgrade-analyzerの詳細な実装仕様を定義し、開発・保守・運用の指針を提供する。

### 1.2 設計の範囲
- プロンプトテンプレートの詳細仕様
- レポートテンプレートの詳細仕様
- ファイル管理の詳細仕様
- エラーハンドリングの詳細仕様

## 2. プロンプトテンプレート設計

### 2.1 ファイル構成
- **ファイル名**: `templates/prompt_template.md`
- **文字エンコーディング**: UTF-8
- **改行コード**: LF

### 2.2 テンプレート構造

#### 2.2.1 ヘッダー部分
```markdown
# バージョンアップ影響調査プロンプトテンプレート

## ⚠️ 必須前提条件
このプロンプトテンプレートは、**Cursor最新版 + Browser機能ON** での使用を前提としています。

### 事前準備チェックリスト
- [ ] **Cursorを最新版にアップデート済み**
- [ ] **Browser機能がON** になっている（Settings → Tools & Integrations → Browser Automationで確認）
- [ ] **チャット欄の「＋Browser」がON** になっている
- [ ] バージョンアップ対象の製品名とバージョン番号を把握済み
```

#### 2.2.2 変数設定部分
```markdown
---
【変数設定】※ここだけ編集してください
製品名: {製品名}
バージョンFrom: {バージョンFrom}
バージョンTo: {バージョンTo}
---
```

#### 2.2.3 メインプロンプト部分
```markdown
あなたは、ソフトウェアのバージョンアップ影響分析の専門家です。
公式リリースノート、GitHub、セキュリティアドバイザリなどの一次情報をBrowser機能で調査し、正確で実用的なレポートを作成してください。

**🚀 重要**: 以下の手順で網羅的な調査を実施してください：

1. **リリース状況の確認**:
   - まず、対象製品の最新リリース状況を確認
   - 指定されたバージョンが実際にリリースされているか検証
   - リリースされていない場合は、最新の利用可能バージョンを特定

2. **バージョン差分の網羅的調査**:
   - FromバージョンからToバージョンまでの**全中間バージョン**を特定
   - 各バージョンのリリースノートを個別に調査
   - 累積的な変更点を整理し、段階的な影響を分析

3. **一次情報の優先**:
   - 公式リリースノートを最優先で調査
   - GitHub Releases、公式ブログ、セキュリティアドバイザリを確認
   - 推測や不確実な情報は避け、事実に基づいた分析のみを提供
```

### 2.3 変数置換仕様

#### 2.3.1 変数一覧
| 変数名 | 説明 | 例 | 必須 |
|--------|------|-----|------|
| {製品名} | バージョンアップ対象の製品名 | Next.js, React, PostgreSQL | 必須 |
| {バージョンFrom} | 現在のバージョン | 15.4, 18.2.0, 14.1 | 必須 |
| {バージョンTo} | アップグレード先のバージョン | 15.5.3, 18.3.1, 15.0 | 必須 |

#### 2.3.2 変数置換処理
1. スラッシュコマンド実行時に引数を取得
2. プロンプトテンプレートを読み込み
3. 変数プレースホルダーを実際の値で置換
4. 置換されたプロンプトをAIに送信

### 2.4 分析手順の詳細

#### 2.4.1 リリース状況確認手順
```markdown
**⚠️ 必須調査手順**:
1. **リリース状況の検証**: 指定されたバージョンが実際にリリースされているか確認
2. **中間バージョンの特定**: FromとToの間にある全バージョンを特定
3. **段階的差分分析**: 各バージョン間の変更点を個別に調査
4. **累積影響の評価**: 全変更点を統合して総合的な影響を分析
```

#### 2.4.2 調査項目の詳細
```markdown
## 調査項目

以下の観点で網羅的に調査してください：

### 1. メタ情報
- **調査日**: 現在の日付を動的に取得（YYYY-MM-DD形式）
- **リリース状況確認**: 指定バージョンのリリース状況（リリース済み/未リリース/最新バージョン）
- **中間バージョン一覧**: FromとToの間にある全バージョンのリスト
- **セマンティックバージョン分類**: MAJOR/MINOR/PATCHの判定
- **重要度**: 高/中/低（プロジェクトコンテキストを考慮）

- **バージョン範囲**: From → To の全バージョン
- **総変更数**: 全バージョンでの累積変更数
- **Breaking Changes数**: 互換性破壊の変更数
- **セキュリティ修正数**: CVE修正の数
- **新機能数**: 追加された機能の数
- **バグ修正数**: 修正されたバグの数

### 3. バージョン別変更ログ（全件）
- From、全中間バージョン、To を含むすべてのバージョンを古い順に並べ、`#### {バージョン番号}（リリース日: YYYY-MM-DD）` の小見出しを作成
- 各バージョン小見出しではそのバージョンで発生した全変更（Breaking / Feature / Security / Bugfix / Deprecation 等）を漏れなく列挙し、省略しない
  - 各行に変更種別、概要・影響範囲、一次情報（公式リリースノート、GitHub Releases、セキュリティアドバイザリなど）へのリンクを必ず記載
  - 複数ソースがある場合は複数リンクを併記し、必要に応じてサブ箇条書きで整理する
```

### 3.3 セクション詳細仕様

#### 3.3.1 メタ情報セクション
- **目的**: レポートの基本情報を提供
- **必須項目**: 調査日、製品名、バージョン情報、重要度
- **形式**: 表形式（Markdown Table）

#### 3.3.2 差分サマリセクション
- **目的**: 変更の概要を一目で把握
- **必須項目**: バージョン範囲、変更数、重要度
- **形式**: 表形式（Markdown Table）

#### 3.3.3 バージョン別変更ログセクション
- **目的**: From〜To の各バージョンで発生した全変更を一次情報付きで網羅
- **必須項目**: バージョン番号、リリース日、変更種別、変更内容、影響範囲、一次情報リンク
- **形式**: バージョンごとに `#### {バージョン番号}（リリース日: YYYY-MM-DD）` の小見出しを設け、箇条書きで全変更を列挙（省略不可）

#### 3.3.4 主要変更点セクション
- **目的**: 詳細な変更内容を分類して提示
- **分類**: Breaking Changes、セキュリティ修正、バグ修正、新機能追加、パフォーマンス改善、廃止予定機能
- **形式**: セクション別の詳細説明

#### 3.3.5 依存関係の既知問題セクション
- **目的**: 推移的依存関係の問題を明示
- **必須項目**: 問題内容、影響範囲、対応方法
- **形式**: 問題別の詳細説明

#### 3.3.6 テスト戦略セクション
- **目的**: 実践的なテスト観点を提供
- **分類**: 高優先度、中優先度、基本テスト
- **形式**: 優先度別のテスト項目

#### 3.3.7 リスクアセスメントセクション
- **目的**: リスクの評価と対応策を提示
- **必須項目**: リスク項目、発生確率、影響度、対応策
- **形式**: 表形式（Markdown Table）

## 4. ファイル管理設計

### 4.1 ファイル命名規則

#### 4.1.1 レポートファイル
- **形式**: `{製品名}_{バージョンFrom}_to_{バージョンTo}_{YYYYMMDD}_{HHMMSS}.md`
- **例**: `nextjs_15.4_to_15.5.3_20251008_143022.md`
- **文字制限**: ファイル名は255文字以内
- **特殊文字**: ファイル名に使用できない文字は置換

#### 4.1.2 製品名の正規化
```javascript
// 製品名の正規化ルール
function normalizeProductName(productName) {
  return productName
    .replace(/[<>:"/\\|?*]/g, '_')  // 特殊文字をアンダースコアに置換
    .replace(/\s+/g, '_')           // スペースをアンダースコアに置換
    .replace(/_+/g, '_')            // 連続するアンダースコアを1つに
    .replace(/^_|_$/g, '')          // 先頭・末尾のアンダースコアを削除
}
```

#### 4.1.3 バージョン番号の正規化
```javascript
// バージョン番号の正規化ルール
function normalizeVersion(version) {
  return version
    .replace(/[<>:"/\\|?*]/g, '_')  // 特殊文字をアンダースコアに置換
    .replace(/\s+/g, '_')           // スペースをアンダースコアに置換
}
```

## 5. エラーハンドリング設計

### 5.1 エラー分類

#### 5.1.1 入力エラー
- **E001**: 引数不足エラー
- **E002**: バージョン形式エラー
- **E003**: 製品名不正エラー

#### 5.1.2 処理エラー
- **E004**: Browser機能無効エラー
- **E005**: インターネット接続エラー
- **E006**: AI処理エラー

#### 5.1.3 ファイルエラー
- **E007**: ファイル保存エラー
- **E008**: ディレクトリ作成エラー
- **E009**: 権限エラー

### 5.2 エラーメッセージ仕様

#### 5.2.1 エラーメッセージ形式
```markdown
## ❌ エラーが発生しました

**エラーコード**: E001
**エラーメッセージ**: 引数が不足しています
**解決方法**: 以下の形式でコマンドを実行してください
```
/upgrade-analyzer <製品名> <バージョンFrom> <バージョンTo>
```

**詳細**: 製品名、現在のバージョン、アップグレード先のバージョンをすべて指定してください。
```

#### 5.2.2 エラーメッセージ一覧
| エラーコード | エラーメッセージ | 解決方法 |
|-------------|-----------------|----------|
| E001 | 引数が不足しています | 必要な引数をすべて指定してください |
| E002 | バージョン形式が正しくありません | 正しいバージョン形式で入力してください |
| E003 | 製品名が正しくありません | 有効な製品名を入力してください |
| E004 | Browser機能が無効です | Cursor設定でBrowser機能を有効にしてください |
| E005 | インターネット接続エラー | インターネット接続を確認してください |
| E006 | AI処理でエラーが発生しました | しばらく待ってから再実行してください |
| E007 | ファイル保存に失敗しました | ファイル権限を確認してください |
| E008 | ディレクトリ作成に失敗しました | ディレクトリ権限を確認してください |
| E009 | ファイルアクセス権限がありません | ファイル権限を確認してください |

### 5.3 エラー回復処理

#### 5.3.1 自動回復
- 一時的なエラーの場合、自動的にリトライ
- リトライ回数: 3回まで
- リトライ間隔: 指数バックオフ

#### 5.3.2 手動回復
- ユーザーにエラーメッセージと解決方法を提示
- 必要に応じて設定の確認を促す
- 再実行の指示

## 7. 設定管理設計

### 7.2 設定項目

#### 7.2.1 スラッシュコマンド設定
```markdown
### /upgrade-analyzer

**説明**: ソフトウェア製品のバージョンアップ影響分析レポートを生成します。

**構文**:
```
/upgrade-analyzer <製品名> <バージョンFrom> <バージョンTo> [プロジェクト情報]
```
```

#### 7.2.2 プロンプト設定
```markdown
**動作**:
このコマンドを実行すると、以下のプロンプトが自動的に実行され、**レポートが自動的に`reports/`フォルダに保存されます**：

**⚠️ 重要**: レポート生成後、**必ず以下の手順でファイルを自動保存してください**：
1. 生成されたレポートを`reports/{製品名}_{バージョンFrom}_to_{バージョンTo}_{YYYYMMDD}_{HHMMSS}.md`として**自動的に新しいファイルで保存**
2. **重要**: 既存ファイルは上書きせず、実行のたびに新しいファイルを生成
3. **必須**: ファイル保存を完了し、ファイルパスを報告
4. **確認**: 保存完了を確認し、レポートの品質チェックを実施
```

### 7.3 設定変更手順
1. `.cursorrules`ファイルを編集
2. Cursorを再起動
3. 設定の反映確認
